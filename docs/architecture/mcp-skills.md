# MCP Skills

Faktory embeds three public procedural skills: `edit-model-projects`, `publish-model-releases`, and `manage-model-views`. Their source lives in [`skills/`](../../skills/). Each entrypoint has one curated reference; no scripts, private project data, runtime filesystem scanning, or generated tool help are published.

`FaktoryMcp::new` builds and validates one immutable `Arc<SkillCatalog>` from explicit `include_bytes!` inputs. Invalid embedded content prevents local or hosted router construction with a safe error. The typed `ServerHandler` exposes the catalog alongside the resource-first facade. The `progressive` dependency feature remains solely for existing `progressive::tool_result` serialization; the server does not use a progressive tool surface.

Streamable HTTP advertises the `io.modelcontextprotocol/skills` extension and Resources primitive, but not directory reading. `skills/list` returns all three skills; `skills/get` returns an exact entrypoint manifest; `resources/read` returns each manifest file's exact raw UTF-8 content. Results are complete, private-cache-scoped, with zero freshness TTL. Manifest sizes and lowercase `sha256:` digests cover raw bytes including YAML frontmatter and final newlines. Unknown skill/file URIs fail, not fall back to filesystem access. The Docker Rust build copies the assets before compilation; runtime images need no skill directory.

These are workflow instructions, not permissions. All methods remain behind the existing hosted bearer validation, broad `faktory:use` scope, and default-deny Origin policy. Exact disabled-auth mode still uses the same uncredentialed local transport. The resource-first MCP interface does not change OAuth, browser, protobuf, or artifact access.

The five uniform tools are `create`, `edit`, `destroy`, `execute`, and `query`; ordinary reads use `faktory://` resources. Generated project `AGENTS.md` remains canonical revision-, path-, and exact-lock-specific resource data; it is never a static skill. Protected Index and Dependency Guidance, user Hints, bundle hashes, exact release locks, render/retry without resolution, READY publication, explicit major adoption, last-good image metadata, primary-only shaded views, binary image resources, semantic query images, and view etags retain their contracts in [Model Projects and Dependencies](model-projects-dependencies.md) and [Protocol](protocol.md).
